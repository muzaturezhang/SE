# 工作人员预订管理 UI 开发演示

2026-10-29，B 第五批。页面延续当前摄影、暖白底色、衬线标题与细线布局。此文档是开发预览步骤，不是最终集成或真实支付证据。

## 启动

在工程根目录先停止旧服务，再执行 `./scripts/dev-ui.sh`。仅本机回环启用 `dev,local-staff,booking-ui,account-ui,staff-booking-ui`。打开 <http://localhost:8080/admin/stays>，未登录会先进入本地 STAFF 登录；用户名 localstaff，随机密码只在被 Git 忽略、mode600 的 `.cache/staff-preview/password.txt`，不要发给队友或放进截图。

默认 `dev.sh` 没有演示账号或工作人员预订页面；`dev-staff.sh` 默认仅房间管理。单独启用可以运行 `STAFF_BOOKING_UI_PREVIEW=true ./scripts/dev-staff.sh`。可选 profile 只控制本地 UI 样例，不替代 STAFF 后端授权。

## 样例与操作

启动当天为 D。六条独立虚构工作人员记录，不读取客户 Session 的 UI-DRAFT，也不读取 Room 库存或真实 Booking/Payment。

| 编号 | 入住 | 展示状态 | 固定示例总价 CNY |
| --- | --- | --- | --- |
| STAFF-DEMO-001 | D+10 | 待支付 | 1,960.00 |
| STAFF-DEMO-002 | D+10 | 已确认 / 已支付 | 3,360.00 |
| STAFF-DEMO-003 | D+11 | 支付失败 | 1,960.00 |
| STAFF-DEMO-004 | D+11 | 支付待核对 | 6,560.00 |
| STAFF-DEMO-005 | D+12 | 已过期 | 1,960.00 |
| STAFF-DEMO-006 | D+12 | 待支付 / 待报价 | 空值，不是零元 |

1. 从管理导航在房间与预订之间切换；当前页面有下划线标记。
2. 编号支持部分匹配、去首尾空白、不区分大小写；只接受最多40位字母/数字/短横线。
3. 入住日期是精确日期筛选，可查历史；与客户未来入住验证不同。状态筛选与其他字段取交集。
4. 当 D=2026-10-29，输入002、2026-11-08、已确认，应仅显示002。进入详情，再返回列表，保留这三个条件。
5. 输入不存在编号或历史日期，显示空状态与重置入口。无效日期/状态/编号返回400，保留筛选输入和可读错误；不存在详情返回404。
6. 查看004的支付核对提示、006的待报价文案。详情分别展示预订/支付状态、住期/间数/晚数、联系资料与费用快照。
7. 状态变更与支付核对按钮禁用，没有写接口、收款、取消/改期、库存释放、导出或邮件。

所有页面要求ROLE_STAFF；CUSTOMER或匿名不可读取记录。真实本地登录沿用A接入前的临时方案，账户UI的“登录后展示”不授予STAFF。页面no-store、动态文本转义，已有管理POST和退出的CSRF保持启用。

## 接入前交接

B 的代码在 `web.staffstay` 和 `templates/staffstay`。`StaffStayPageGateway` 只有 search/find，只接收后端 Authentication 提供的 staffId。真实适配器必须由A/C确认员工身份与服务授权、查询范围、分页/排序、独立预订/支付状态映射、成交价格快照、联系字段/房号和错误；所有展示枚举与签名仍为草案。

不能把当前匿名客户preview端点或本地虚构数据当作真实订单源。状态变更、支付核对和库存事务由C/D实现后另行接入；Q8取消/改期/提醒的实现范围仍未确认。当前6条不分页，真实数据量与稳定分页契约待C评审。
