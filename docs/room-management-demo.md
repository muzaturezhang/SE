# 独立演示房间管理

先停止旧服务，然后在工程目录运行 `./scripts/dev-staff.sh`。打开 <http://localhost:8080/admin/rooms>；用户名 `localstaff`，密码在本机 `.cache/staff-preview/password.txt`，可用文本编辑器查看。密码文件权限为 600、被 Git 忽略，不分享给队友或提交仓库；队友运行脚本会生成自己的密码。

1. 登录后可见初始 8 间房，C105 已停用。按庭院/停用筛选只显示 C105。
2. 点击“新增房间”，填写 C106、庭院客房、启用。成功后清单为 9 间。
3. 从“查看客房页”查询启动日 D+10 至 D+12，庭院可用数量从初始 4 变为 5。
4. 返回管理，点击 C106 的“停用…”后确认停用。重查同住期，庭院可用回到 4；C106 仍在管理列表，可编辑为启用。
5. 编辑 C101：有当前/未来占用，提交停用或更换房型会收到冲突提示；不修改原数据。
6. 在“房型基础价”调整庭院价为 1234.56，客房页立即显示 ¥1,234.56。可改回 980.00。
7. 页面上的退出按钮提交 CSRF 保护的 POST；退出后访问管理页需要重新登录。

重启恢复 fixture，包括清除新增房间和房价修改；原始 JSON 文件不会被后台修改。默认 `./scripts/dev.sh` 无管理账号，管理页匿名访问为 403。可选预览 profile 只能配合 dev、回环监听运行，不允许与 mysql/test 共用。

正式认证接 A；有效占用与 Booking 事务接 C/D；MySQL 与持久化接 D。不要将本地账号或内存预览当作最终集成。
