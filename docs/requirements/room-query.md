# Room 查询需求与验收条件

Owner：B。当前批次：房型浏览、日期与数量查询、基础价格展示。状态：模块实现依据；跨模块方法、DTO 和 schema 仍为待 C/D 评审的草案。

| ID | 需求 | 验收条件 |
| --- | --- | --- |
| FR-ROOM-001 | 浏览房型 | 未提交日期时，显示内存样例目录中的房型、介绍、配图、特征和每间每晚基础价，不声称有实时可用数量。 |
| FR-ROOM-002 | 查询可用房型 | 输入合法入住日期、退房日期、正整数房间数，可选房型；后端只返回整个入住区间内连续可用房间数不少于请求数量的房型。 |
| FR-ROOM-003 | 按日期计算可用性 | 区间为 [入住日, 退房日)，任何重叠占用均排除整间房；停用房间排除；同一间房的重复占用不重复扣减。 |
| FR-ROOM-004 | 展示基础价格 | 显示房型的 CNY 每间每晚价格，领域数据使用整数分；不计算会员折扣或 booking 总价。 |
| FR-ROOM-005 | 拒绝非法查询 | 过去入住日期、空缺日期、同日或逆序退房、非正整数数量、无法解析的输入和未知房型，返回 HTTP 400 与可读提示。绕过浏览器校验仍被后端拒绝。 |
| FR-ROOM-006 | 无结果与查询只读 | 没有符合数量的房型时显示无结果提示；重复相同查询不改变库存、不创建 booking、不占用房间。 |

日期以共享 Asia/Shanghai Clock 判断当天。暂不增加最大住宿晚数或单笔最大房间数；超出可用数量的合法请求返回无结果，无法绑定为整数的数量返回 400。

示例房型、价格、房号与占用均为开发数据，来自 `data/fixtures/room-inventory.json`。占用以应用启动当天为基准使用相对天数，重启重新加载。对接真实 Repository 后需要复核数据库一致性；本批不提供库存预留、锁、付款、会员或管理员写操作。
