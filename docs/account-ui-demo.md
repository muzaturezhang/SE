# 第四批账户与会员 UI 演示

先停旧服务，在工程目录执行 `./scripts/dev-ui.sh`。打开 <http://localhost:8080/preview/account/login>。默认 dev.sh 不提供本组预览；此处与 STAFF 管理登录相互独立。

1. 点“查看注册页面”，保留演示姓名或改为“演示访客”，邮箱用 example.invalid 域名，两个密码框填写相同临时演示文本。点击“预览注册结果”。这只生成姓名/邮箱展示结果，不创建账号。
2. 密码不一致会收到400提示，两个密码框清空，姓名/邮箱保留；也可查看“邮箱已注册提示示例”。密码必填/最多256字符只是UI边界，实际密码策略待A确认。
3. 从结果页继续登录预览，邮箱会从本会话回填。同邮箱可在个人中心延续刚才的演示姓名。输入临时文本后点击“预览登录后页面”，没有真实认证或获得CUSTOMER/STAFF权限。
4. 个人中心展示资料与“我的预订”入口；“退出账户预览”只清理本模块资料，预订草稿和真正的STAFF登录不受影响。
5. 会员页切换未开通、有效、已过期、待确认。日期是布局示例，费用和折扣等待服务返回，切换不改变任何真实会员状态。
6. 过期例子点击续费。若已退出账户展示，会先进入登录预览并保留续费返回位置；完成后回到续费方案。开通/续费的付款按钮禁用，待确认状态也不提供重复付款。
7. 登录失败和邮箱重复例子是只读链接。真实后端错误、认证、会员规则和邮件均未实现。

next只允许已知站内预览地址；例如从选房继续时可回到带原日期/数量的 /preview/stays/new，拒绝站外或管理地址。姓名/邮箱只存在当前Session，重启或退出展示后清除；密码不会进入Session、日志或文件。不要使用真实账号密码。

对接A时需要正式注册/登录/本人资料和会员服务，对接C时需要会员费用支付与核对；另建CUSTOMER保护入口并替换演示文案，不能直接把真实账号服务挂到当前匿名预览路由。完整缺项见 b-handoff-checklist.md。
