# 第三批预订流程 UI 演示

先停止旧服务，再在工程目录运行 `./scripts/dev-ui.sh`。打开 <http://localhost:8080/preview/stays/new>；此 UI 演示不需要登录，管理页仍需独立 STAFF 登录。默认启动 `dev.sh` 没有这组预览入口。

1. 客房页选择启动日 D+10 至 D+12、2间，点击查询结果中庭院客房的“安排入住 · 演示”。确认页应带入同一日期和2间，显示可用4间。
2. 保留演示住客和 guest@example.invalid，点击“预览订单与支付页”。生成当前会话 UI-DRAFT，详情显示相同安排与资料，最终金额为“待预订服务报价”。没有创建实际订单或占库存。
3. 打开支付页，按钮为禁用的“支付服务待接入”。通过下方链接查看待支付、支付成功、支付失败、待核对、过期5种固定状态。
4. “我的预订”显示当前草稿和5条示例；“查看空状态示例”只切换展示，不删除任何记录。
5. 在确认页把数量改为99提交，得到409库存不足提示，输入保留；空姓名、非法邮箱、日期和数量也有后端校验。
6. 用另一个独立会话直接访问 UI-DRAFT 会返回404。草稿只留当前会话，重启/会话失效后消失，重复提交只替换一个草稿。

本次用例D=2026-10-28，对应演示日期2026-11-07至2026-11-09。固定支付示例的金额是预写页面快照；动态选房不推导总价、会员折扣或付款结果。页面没有付款账号输入、支付网关调用、邮件发送或自动超时释放。

接入顺序：A提供CUSTOMER身份 → C确认页面Gateway所需报价/创建/列表/详情/支付服务 → B写真实适配器与受认证保护的Controller → C/D完成库存事务后联调。不要将当前匿名preview地址直接接到真实订单数据。
