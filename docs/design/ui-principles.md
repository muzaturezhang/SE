## 平等 多样性与包容性

公共布局使用lang=zh-CN、跳转主要内容链接；表单使用真实label，状态除了颜色也有文字，CSS提供focus-visible与prefers-reduced-motion支持。主要客户/账户/预订与员工页面已做开发响应式检查；Room表格允许局部滚动。图片提供alt，装饰元素用aria-hidden，详情可用原生dialog与键盘关闭。这些都能在layout.html、app.css、app.js和各模板定位。

中文界面和英文辅助标签不等于双语本地化。当前没有宣称满足WCAG等级、读屏兼容或所有低视力需求；字号/对比、200%缩放、完整键盘顺序、屏幕阅读器、触屏目标、认知易读性和不同文化/输入方式仍应由真实测试确认。姓名不设置拉丁字母限制，金额标明CNY，日期显式年月日；真实姓名/邮箱/密码策略还需A确认，不能把演示上限当适用于所有人的规则。

后续使用匿名合成资料进行开发检查；真实参与者需实际招募与记录，不伪造人数、访谈、满意度或签名。Q7如需用户研究，由团队按实际流程执行并记录同一build。

## 原型方式选择与替代

当前使用可运行的Thymeleaf页面配合本地fixture作为交互原型，直接验证服务端校验、路由、CSRF、Session隔离与响应式布局，并能复用到后续实现。代价是设计评审依赖本机Java服务，非开发队友不如可点击设计稿方便，业务规则未接入时必须持续标注演示。

可考虑Figma可点击原型作早期页面布局和团队批注的替代方式；它更易分享和比较视觉变体，但静态交互不能证明服务器授权、库存并发或支付正确性。这里是工具取舍分析，没有声称已经创建或测试过Figma原型。最终工具评价还需结合团队实际使用与课程要求补证。
